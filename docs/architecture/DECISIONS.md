## CCR-003 — Backend-owned browser voice binding (proposed)

- Problem/evidence: a LiveKit job process cannot safely own a second in-memory `Application` while the HTTP Console and `ProjectionHub` show the authoritative session. Browser microphone access also needs a narrowly scoped room token and authenticated worker observation channel.
- Canonical owner/reviewers: Runtime/API Owner A for Application, HTTP, and ProjectionHub; Voice Owner A for LiveKit worker transport; Truth Owner D for output start/terminal acknowledgement; frontend Owner D for Composer transport state. Review and acceptance remain pending on this PR.
- Old → new: the existing `Application.start_session` global dependencies remain the default; an optional session-scoped dependency/registry override is added. `POST /api/v1/voice/sessions` creates a server-owned room/session binding and short-lived microphone-only token. An internal worker WebSocket accepts only five validated transport observations; backend translation journals canonical facts. `RemoteVoiceOutput.emit` waits for matching playout-start proof before `SpeechEmissionStarted`.
- Compatibility: additive optional runtime parameters and endpoints; existing domain models, events, reducer semantics, and serialized schema versions are unchanged. No migration is needed. Missing credentials and stale worker generations fail closed. Existing text/DEMO sessions use the old composition path.
- Producers/consumers: LiveKit worker produces STT/VAD/playout observations; backend transport adapter consumes them and produces journal candidates; backend dispatcher produces exact approved speech commands; frontend consumes only the backend projection and uses LiveKit for audio.
- Files/tickets/tests/demo: `backend/interlock/main.py`, `backend/interlock/adapters/http.py`, `backend/interlock/adapters/voice_transport.py`, `backend/interlock/adapters/livekit_agent.py`, frontend API and Composer transport files, `HTTP_API.md`, `CONFIGURATION.md`, `INTERFACES.md`, `REPOSITORY_BLUEPRINT.md`, VCE-001, T-VOICE-01, and browser Samsung DEMO.
- Migration/fallback/risk: a worker disconnect cannot establish whether speech was heard and must not fabricate a terminal fact. Browser session tokens expire in five minutes; bindings retain session transport metadata for at most one hour. Browser voice fails unavailable without server-side LiveKit and worker credentials. Real audio latency, provider behavior, and deployment topology remain unverified until a credentialed run.

## CCR-001 — World-effect ingress and verification targeting (accepted)

- Problem/evidence: the reducer previously overwrote `state.effects[effect_id]` with changed content; the old `VerifyOutcome(operation_id)` cannot identify a conflicting physical effect or duplicate physical writes under one logical action. The documented append-only ledger/projection was not executable from these semantics.
- Canonical owners/reviewers: Runtime A owns command/reducer ingress; Execution C owns EXE-005 interpretation/projection; Truth D consumes the projection. Owner A approved the implementation direction in [PR #24](https://github.com/rupeshhh007/404-samsung/pull/24); Owner C approved in [review 5340917452](https://github.com/rupeshhh007/404-samsung/pull/24#pullrequestreview-5340917452); Owner D approved in [review 5341306763](https://github.com/rupeshhh007/404-samsung/pull/24#pullrequestreview-5341306763), all against `0ff2d1301395767b5ecc38bed6aa78ced55db8f6`.
- Old → new: mutable/latest row by `effect_id` and operation-only verification → immutable local observation by `effect_id`, provider/logical grouping for current certainty, linked compensation, optional `provider_effect_id` verification target, and explicit verification evidence using the existing `EvidenceRecord.provenance`. Existing operation-only commands retain their meaning.
- Compatibility: additive command fields with `None` defaults; no serialized event/entity field added, removed, or reinterpreted and no schema-version bump. Previously accepted overwrites become deterministic protocol violations (intentional fail-closed behavior). Existing retained observations need no migration; replay derives the same result from preserved event order.
- Producers/consumers: EXE-005 `EffectInterpreter`, provider adapters and verifiers produce observations; reducer, projection, ClaimGraph/TRUTHLOCK, reconciliation, and speech consume them. `ToolRuntime` remains a normalized observation producer, not a world-truth authority.
- Files/tickets/tests/demo: `DOMAIN_MODEL.md`, `EVENT_MODEL.md`, `STATE_MACHINES.md`, `INTERFACES.md`, `WORLD_EFFECTS.md`, `runtime/commands.py`, `runtime/reducer.py`, `backend/tests/test_world_effect_contract.py`, `INT-002`, `EXE-005`, `TRU-002`, `EXE-006`; simulated late-booking demo must retain the 11:00 fact while showing uncertain current state on authoritative conflict.
- Migration/fallback/risk: old `VerifyOutcome` consumers can ignore optional targets but must not silently resolve a targeted conflict by operation-only absence; fail closed or escalate until EXE-005 verifier support exists. The reducer cannot by itself prove current-world resolution or provider compensation. Review physical-ID reuse, cross-provider namespaces, and evidence authority before enabling automatic repair.
- Accepted resolution: `supersedes_effect_id` remains compensation-only. A verification observation identifies its target and all prior authoritative observations through an immutable `EvidenceRecord` of kind `world_effect_verification`; its provenance carries the physical ID, triggering event ID, provider readback request ID, and covered observation IDs. `WORLD_EFFECTS.md` defines the fail-closed projection rule. Automatic conflict repair remains disabled until EXE-005 implements and validates that rule.

## CCR-002 — Sequence-pinned speech approval and correction lifecycle (proposed)

- Problem/evidence: Async TRUTHLOCK decisions could race concurrent claim mutations, allowing speech acts approved against stale snapshots to be queued and emitted without revalidation. Mid-emission invalidation lacked clean handling for partially played audio (`heard`). Adapter output failures lacked a canonical event, and correction triggering had no runtime command representation to unblock Owner D (TRU-004).
- Canonical owners/reviewers: Runtime A owns reducer/commands; Truth D owns TRUTHLOCK/speech; Intel B for correction semantics.
- Old → new: Unpinned approval and unlinked speech invalidation → sequence-pinned (`through_sequence`) and claim-versioned (`claim_versions` matching `ClaimRecord.updated_by_event_id`) approval with retry on staleness, deterministic post-dispatch (`QUEUED` and `EMITTING`) invalidation and cancellation tracking via `cancellation_pending` and `correction_pending`, `RequestSpeechCorrection` runtime command, fail-closed terminal contradiction enforcement, and `SpeechEmissionFailed` event.
- Compatibility: Additive model/event/command fields with default values; schema_version remains 1; fail-closed on missing or future sequence pins; no breaking serialization changes.
- Producers/consumers: TRUTHLOCK produces approvals; output adapter produces emission facts/failures; reducer consumes them and emits commands; TRU-004 consumes `RequestSpeechCorrection` to plan corrective speech acts.
- Files/tickets/tests/demo: `DECISIONS.md`, `DOMAIN_MODEL.md`, `EVENT_MODEL.md`, `STATE_MACHINES.md`, `INTERFACES.md`, `SPEECH_AND_OUTPUT.md`, `EVENT_JOURNAL_AND_REDUCER.md`, `TRACEABILITY.md`, `models.py`, `events.py`, `commands.py`, `dispatcher.py`, `reducer.py`, `truthlock.py`, TRU-003, TRU-004, RUN-002.
- Migration/fallback/risk: Missing sequence pins fail closed with `MISSING_SPEECH_PIN`. Stale approvals retry via `ValidateSpeech` instead of blocking permanently. Centralized replay suppression guarantees zero external commands on replay.
- Replacement semantics: the reducer re-emits `RequestSpeechCorrection(parent)` only when canonical reducer context proves the dead, unheard correction attempt became obsolete through claim advancement: direct APPROVED invalidation, a pre-queue claim-version mismatch, or an active QUEUED/EMITTING attempt previously marked `correction_pending=True`. Live or heard siblings suppress replacement. Generic `SpeechActBlocked`, explicit user/barge-in cancellation (`cancellation_pending=True`, `correction_pending=False`), and plain `SpeechEmissionFailed` do not automatically retry. A heard correction satisfies its parent; if that correction later becomes stale, it enters `CORRECTION_REQUIRED` and creates a distinct correction-of-correction obligation. Replay derives the same state and emits no commands.
