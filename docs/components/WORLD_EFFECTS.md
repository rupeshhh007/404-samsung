# World Effects

The ledger is append-only evidence of observed external reality. Result interpretation uses descriptor confirmation semantics and authority: request receipt creates evidence but not a committed effect; authoritative booking confirmation creates a new immutable `EffectRecord` observation. `effect_id` identifies the local observation, `provider_effect_id` the provider-qualified physical effect (namespace raw IDs when providers can collide), `logical_action_id` the intended user action, and `operation_id` the local execution. These identities are not interchangeable.

A stale operation's confirmed effect is always recorded. Repeating the exact same `effect_id` and content is idempotent; additional provenance uses a distinct observation ID and is grouped in the derived projection rather than mutating the old record. A second distinct provider effect under one logical/idempotency action is retained as a duplicate-effect incident. Conflicting authoritative observations for one physical effect are both retained and make **current-world projection** uncertain; they do not rewrite historical truth or downgrade the operation's confirmed effect dimension. Both conflicts schedule targeted verification. Unknown outcomes remain explicit until `appointment.get` or equivalent authoritatively proves commit/absence.

The authoritative world projection is derived from all retained observations, grouped by provider-qualified physical effect ID and then logical action. A group is confirmed when its authoritative observations agree on material physical facts (`state`, `effect_type`, `subject`, `parameters`), with linked compensation interpreted separately. Exact repeated facts leave that result unchanged. Contradictory authoritative facts make current certainty unresolved; neither sequence nor timestamp resolves them. A weak timeout/unknown observation cannot undo a committed fact. Distinct physical IDs under one logical action remain distinct even if they constitute a duplicate-write incident. Tests: T-WLD-01, T-IDM-01, T-UNK-01.

### Explicit verification and current projection (accepted contract; EXE-005 implementation pending)

EXE-005 records the trusted provider readback as `EvidenceRecorded` **before** its new `WorldEffectObserved`. The new effect references an existing `EvidenceRecord` with `source=TOOL`, `authority=AUTHORITATIVE`, and `kind="world_effect_verification"`. That evidence has a content reference/hash for the actual readback and these provenance keys: `provider_effect_id` (equal to the effect's target), `verification_request_event_id` (the conflict/uncertainty event that caused the targeted `VerifyOutcome` and the new effect's `causation_id`), `provider_request_id` (the readback request, not the original write acknowledgement), and `verification_of_effect_ids` (a sorted, unique, nonempty list of **all** earlier authoritative observation IDs in that physical group). EXE-005 must validate this provenance, its trusted verifier producer, and the readback's descriptor-specific finality/authority before using it; a later ordinary callback or an uncorrelated claim is not verification. No new entity, enum, or event is required.

For a conflicting physical group, select the state proven by an authoritative verification observation only when its evidence targets that group, covers all authoritative observations that existed at verification, and proves one decisive physical state. All older observations remain immutable history. A later observation agreeing with that state does not undo it; a later contradictory observation is uncovered and makes current certainty unresolved again until a new scoped verification covers the enlarged conflict. Two incompatible verification observations without a decisive verification covering **both** remain unresolved. Missing/weak/malformed provenance, an ambiguous readback, or a verifier unable to prove absence also leaves the group unresolved. Never select by arrival order alone. The logical-action projection must additionally flag multiple confirmed physical IDs rather than silently choosing one; consequential claims and repair remain blocked while the relevant group is unresolved. EXE-005 owns implementation and `T-WLD-01` projection tests for A/B conflict, A- and B-supporting C, late ordinary C, insufficient/conflicting verification, replay, duplicate physical IDs, and compensation.

An authoritative `COMPENSATED` observation links to a prior `COMMITTED` observation of the same physical effect via `supersedes_effect_id`; the commit remains in history while the current projection reflects confirmed compensation. A failed compensation leaves the committed booking current unless stronger authoritative physical evidence contradicts it. An unknown compensation does not claim success and requests targeted verification. Conflicting authoritative compensation facts leave current certainty unresolved under the same verification rule; no latest-write-wins.

## Implementation contract

- Purpose: preserve every authoritative external effect and derive the current observed-world projection.
- Non-responsibilities: selecting desired intent, invoking tools, or deciding compensation.
- State: reducer-owned append-only `EffectRecord` map plus indexes by provider effect ID, logical action, and subject.
- Inputs: validated `ToolResultObserved`, verification evidence, descriptor confirmation semantics. Outputs: `EvidenceRecorded`, `WorldEffectObserved`, and divergence-evaluation commands.

Decision procedure: acknowledgement → evidence only; confirmed final/verification → construct authoritative effect; failed-before-commit → FAILED without a committed effect; timeout/ambiguous post-dispatch → OUTCOME_UNKNOWN; confirmed provider compensation → append a `COMPENSATED` observation referring to the prior committed `effect_id` while history remains. Failed or unknown compensation never manufactures a `COMPENSATED` observation; if represented as a separate failed/unknown observation linked to the prior effect, it requires verification when the provider boundary was crossed. Exact repeated observation ID/content is idempotent; same ID with changed content is a protocol violation. Distinct conflicting observations and duplicate physical effects remain in history. Verification uses the optional `provider_effect_id` target; duplicate physical effects require separate targeted commands.

For bookings, effect subject is `{resource:"appointment", provider_booking_id, center_id}` and parameters include `requested_slot` and `confirmed_slot`. A mismatch from intent still enters the ledger and triggers divergence. Acceptance: `T-WLD-01`, `T-IDM-01`, `T-UNK-01`, `T-INV-I4-P`, `T-INV-I4-N`, `T-INV-I9-P`, and `T-INV-I9-N`. Owner C; depends on EXE-004 and TRU-001.
